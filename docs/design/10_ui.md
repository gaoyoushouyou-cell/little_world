# 10 UI

## 参考にする既存の 2D ゲーム

| 参考作 | 取り入れる点 |
|---|---|
| ゆめにっき | メニューが最小限。説明しない |
| Hollow Knight | 普段はほぼ何も表示しない HUD。地図とピン。装備枠の考え方（エフェクトの木の見せ方） |
| Terraria | ホットバーと所持品の格子。作れるものだけが並ぶ加工の一覧。建築時の置き場所の予告表示 |
| Stardew Valley | 倉庫の操作の軽さ。説明（ツールチップ）の出し方 |
| Celeste | アシスト機能とアクセシビリティ設定 |
| ゼルダの伝説（夢をみる島） | ハートの HUD。状況に応じた操作のヒント |
| Hades | 図鑑の書き方（日記の見せ方） |

## 方針

1. **HUD は状況に応じて出す**。普段は mood の印だけ。HP は戦闘規則があるエリアだけ、高さメーターは縦型の塔だけ。しばらく操作しないと薄く消える
2. **メニューは1か所**。一時停止で開き、タブで「エフェクト / 持ち物 / 地図 / 日記 / 設定」
3. **キーボード・ゲームパッド・マウスのどれでも全画面を操作できる**。キーの割り当ても変更できる
4. **仕組みは明快に、夢の中身は説明しない**（[00_overview.md](00_overview.md)）
5. **大事な情報は深さの狂いの影響を受けない**（mood の印、HP、所持品の数など）

## HUD のイメージ

```
┌──────────────────────────────────────────┐
│ ◐青·月                          ◇ 2/5   │  ← mood の印（色＋記号）／このエリアの未取得かけら
│                                          │
│              （ゲーム画面）               │
│                                          │
│ ♥♥♥♡     （戦闘エリアのときだけ表示）       │
│                     [E] 座る              │  ← 状況に応じた操作のヒント
└──────────────────────────────────────────┘
```

揺れるかけらを持っているとき・沈みの重さが足りないときの表示も、同じ仕組みの HUD 部品として足す。

## 拡張できる UI の作り

- 画面に重ねる UI は **Preact + ドット調の CSS**（`image-rendering: pixelated`、整数倍の拡大）
  - 組み込みブラウザでアクセシビリティツリーを読めるので、UI の検証を自動化しやすい
- UI の部品も **1部品 = 1ファイルで自動登録**（`src/ui/`）。各部品は次を申告する
  - **置き場所**：HUD の左上、メニューのタブ、ポップアップ、通知、操作のヒント など
  - **表示条件**：共通の条件の書き方を使う（例：`{ "rule": "combat" }` のときだけ HP）
  - **入力の優先度**：部品が重なったとき、どれが操作を受け取るか
- **見た目の値（色・余白・文字）は一か所の定義**（テーマトークン）にまとめる。mood によって UI の色も変わる
- 文字は `content/i18n/ja.json` に分ける（将来の英語版に備える）
- 日本語のドットフォントは **再配布できるライセンス**のもの（PixelMplus、美咲フォントなど）から選び、ライセンス表記を同梱する

## アクセシビリティ

- 文字の大きさ
- **起動時に光過敏の注意を表示**
- **点滅の抑制**：点滅の代わりに動き・音で不気味さを残す（深さの狂いは色を変えないので、色の変化は代わりに使わない）
- 画面揺れのオフ
- 色覚への配慮：mood の色に記号と模様を付ける
- キーの割り当て変更

## ユーザビリティテスト

| 段階 | 担当 | 内容 |
|---|---|---|
| 1. チャットでの下書き | Claude → ユーザーが確認 | 文字の図で画面の構成を決める |
| 2. ヒューリスティック評価 | Claude | ニールセンの10原則に照らして各画面を点検 |
| 3. 自動検査 | Claude | キーボードだけですべてに到達できるか、文字のはみ出し、コントラスト、拡大率ごとの表示崩れ、よく使う操作の手数を組み込みブラウザで確認 |
| 4. シナリオ操作 | Claude | 組み込みブラウザで実際に操作し、スクショで確認 |
| 5. 実際に遊ぶテスト | **ユーザー** | 決まった課題をこなし、迷ったところを伝える。開発中だけ操作の記録（時間、押し間違い、メニューを開いていた時間）をローカルのファイルに残し、Claude が分析する |

Claude は実際のプレイヤーではないので、「迷う」「気持ちいい」の最終判断は5で決まる。1〜4は明らかな問題を先につぶすための段階。

### 主な課題と目標の手数
| 課題 | 目標 |
|---|---|
| 地図でこのエリアの残りのかけらを確認する | 2操作以内 |
| エフェクトを解放する | 4操作以内 |
| エフェクトの解放を取り消す | 4操作以内 |
| 手持ちの素材を全部倉庫に入れる | 2操作以内 |
| 拠点間でワープする | 3操作以内 |
| エディタで種を植える | ドラッグ1回とメモの入力 |

公開版では閲覧者の操作を記録しない。
